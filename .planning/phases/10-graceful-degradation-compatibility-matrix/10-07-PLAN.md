WebKit, and Firefox — the empirical evidence Plan 08 needs to document the true
per-capability floor (COMPAT-05), including resolving RESEARCH.md's open
assumption A2 (Firefox's actual current ARIA-reflection support).

<assumption_delta_decision>
COMPAT-04 widens the tested-engine matrix from singular to plural: the primary
noun this plan's config, CI wiring, and every future browser-lane spec must
reason about is now "the supported engine set" (chromium + webkit + firefox),
not "Chromium" alone. Decision: PROMOTE — the `browser` project's instances
array is engine-parameterized (a list, not a single hardcoded provider), and
this plan's `include`-scoping keeps that list cheap to extend later. No debt
accepted; the `perf` project deliberately stays Chromium-only by design (D-06),
which is a scope boundary, not an unaddressed gap.
</assumption_delta_decision>

Purpose: catch real WebKit/Firefox quirks in the load-bearing form/focus/dialog
paths and prove this phase's new degradation code isn't Chromium-only-tested,
without fragmenting CI into a parallel toolchain or slowing down the full
correctness lane.
Output: widened `browser` project config, updated CI Playwright install step,
new cross-engine capability-confirmation spec.
</objective>

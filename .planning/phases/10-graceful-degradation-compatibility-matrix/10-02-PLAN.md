<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Light-DOM hidden `<input>` ↔ enclosing consumer `<form>` | The mirrored input is a descendant of the host element, visible to consumer CSS/JS and serialized by native `FormData` — the actual new trust surface this phase introduces (COMPAT-03). |
| compat-forms.ts import ↔ module-level global state | A single boolean flag (`_fallbackEnabled`) flips process-wide on import; no per-instance override. |

## STRIDE Threat Register (ASVS L1; block on high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-10-03 | Tampering | form-participation.ts hidden input | medium | mitigate | Value is authoritative in the owning component and mirrored ONE-WAY into the input (component → input, never input → component); the input carries `hidden` + `aria-hidden="true"` + a reserved internal marker so consumer script targeting it by convention is discouraged, but the mitigation that actually matters is that the component's own render loop re-syncs the mirror on every relevant update, so a consumer mutating the input directly is overwritten on the next sync (V5 input-validation standing control). |
| T-10-04 | Repudiation / double-submit | Native `<form>` submission via two channels | high | mitigate | XOR-gated strictly on `!hasFormAssociation()` in the calling component (Plans 04/05) — form-participation.ts never runs unprompted; a field appearing twice in `FormData` on a supported engine would be a freeze violation, guarded by the must_haves prohibitions in this plan and re-verified with an explicit FormData-parity test in Plan 04. |
| T-10-05 | Tampering | Fallback templating | low | accept | No `innerHTML`/`eval` anywhere in form-participation.ts — `document.createElement` + direct property assignment only (CLAUDE.md Lit-safe constraint); verified by the grep acceptance criterion in Task 1. |
| T-10-06 | Supply chain | compat-forms.ts package entry | medium | mitigate | Static subpath resolved entirely by the consumer's bundler via the `exports` map (same discipline as lazy-load.ts's static bare-specifier `import()`s) — no computed or origin-qualified module path is ever built, so there is no dynamic-code/supply-chain injection seam. |

Highest severity present: T-10-04 (high) — mitigated by the XOR gate design; no threat is left unmitigated at high severity.
</threat_model>

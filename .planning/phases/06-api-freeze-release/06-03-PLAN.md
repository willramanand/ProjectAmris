    (1) SHA-pin — replace `uses: changesets/action@v1` with `uses: changesets/action@<40-char-commit-SHA>` resolving to the commit the `v1` tag currently points at, and keep the human-readable tag in a trailing comment (`# v1.x.y`). SHA-pin every other third-party action in the release and publish workflows (`actions/checkout`, `actions/setup-node`) to full commit SHAs with a version comment.     (2) Green-gate — make the publish step depend on the full gate set (tests + coverage, real-browser a11y, bundle-size) passing, so nothing publishes on a red pipeline. Implement via ONE of: (a) add the gate jobs (or a reusable-workflow call to ci.yml) into release.yml and give the release job `needs: [verify, browser, surface-diff, size]`; or (b) trigger release via `workflow_run` conditioned on the CI workflow concluding `success` on main. Preserve size-limit's node-22 requirement if you inline that gate.

Reconcile publish.yml so the live publish happens on the single green-gated path (either fold it in, or restrict publish.yml to a documented manual `workflow_dispatch` fallback that still runs the gates).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party action → release runner | A floating action tag can be re-pointed to malicious code; only a SHA-pinned action is trusted in the publish path. |
| CI gates → publish | Publish must be reachable only through a fully green gate set; an un-gated publish ships un-verified code. |
| publish token → workflow scope | `GITHUB_TOKEN`/`NODE_AUTH_TOKEN` must be least-privilege and never exposed to a PR-triggered trigger or logs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-07 | Tampering | changesets/action + release actions | high | mitigate | All third-party actions pinned to full commit SHAs with version comments (SHIP-04); no floating `@v1`. |
| T-06-08 | Elevation of privilege | release publish job | high | mitigate | Publish gated behind tests+coverage+a11y+size; `permissions` scoped to `contents: write` + `packages: write`; no PR trigger carries publish scope. |
| T-06-09 | Information disclosure | NODE_AUTH_TOKEN / GITHUB_TOKEN | high | mitigate | Tokens passed only as step `env`, never echoed; single publish path; secondary publish.yml reconciled to avoid an ungated leak. |
| T-06-SC | Tampering | dependencies | low | accept | No new package-manager dependencies; the supply-chain surface is action pinning + token scope, both addressed above. |

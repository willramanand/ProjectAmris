<objective>
Fix FIX-01: the toast dismiss `setTimeout` fallback (toast.ts `_dismiss()`) and its `animationend` listener are currently untracked, so a toast removed mid-dismiss leaves a pending callback that fires `am-close` / mutates a detached node. Establish the phase's shared teardown discipline as a small non-exported helper (`TeardownScope`) and wire toast to it so every timer + animation listener is cleared through `_clearTimer()`.

This is the TRACER for the phase: it proves, end-to-end on one component, the "track every timer + abortable listener; clear them all in the single teardown method that disconnectedCallback already calls" discipline — the same pattern FIX-04 (dialog animation cleanup) reuses in plan 03-02.

Purpose: no pending callback survives a mid-dismiss removal (FIX-01), and a centralized timer/listener discipline replaces ad-hoc cleanup (roadmap goal: "centralize timers").
Output: `src/internal/helpers/teardown-scope.ts` (+ unit test), toast wired to it, and a failing-then-passing mid-dismiss teardown test.
</objective>

Give it a `timeout(handler, ms)` method that calls `setTimeout`, stores the handle, and self-deletes the handle when it fires; a `signal` getter returning the current `AbortController.signal` (for `addEventListener(..., { signal })`); and a `clear()` method that `clearTimeout`s every tracked handle, empties the set, calls `abort()` on the controller, then replaces it with a fresh `AbortController` so the scope is reusable across multiple open/dismiss cycles. Extend `_clearTimer()` so that, in addition to clearing the existing `_timer`, it calls `this._teardown.clear()`. Leave `disconnectedCallback()` unchanged — it already calls `_clearTimer()`, which now drains the dismiss teardown too. Do NOT move the auto-dismiss `_timer` / pause-resume logic into the scope; it already works and must keep its distinct pause/resume handles (behavior-preserving).

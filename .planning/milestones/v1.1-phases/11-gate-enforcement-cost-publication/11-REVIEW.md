# Phase 11: Code Review Report

**Reviewed:** 2026-08-28T03:48:21Z
**Depth:** standard
**Files Reviewed:** 10
**Status:** issues_found

## Summary

Phase 11 flips the CI perf/size guards from report-only to enforcing (GATE-01 brotli
size, GATE-02 runtime counts), staged behind job-level `continue-on-error` soak wrappers
(GATE-03), and adds a zero-dependency cost-cards doc generator with a git-diff drift gate
(DOCS-04).

I verified the parts most likely to be wrong:

- **CI wiring is sound.** `release.yml`/`publish.yml` are untouched by this phase. `api/perf.json`
  is git-ignored and regenerated by `test/perf/harness.ts`, so the perf enforce step compares
  against a fresh report, not a stale committed one. The cost-cards drift gate is deterministic:
  regenerating from the committed baselines produces content byte-identical to the committed
  `docs/cost-cards.md` (git blob is LF; the local CRLF is an autocrlf artifact and does not affect
  the Linux CI checkout). Job-level `continue-on-error: true` is the documented mechanism for
  keeping the workflow-run conclusion `success` while annotating a job red.
- **One real correctness defect in the size enforce path (CR-01):** the gate treats the derived
  `marginal`-over-core rows as first-class regression candidates, so a pure *core-bundle shrink*
  (a genuine improvement, and exactly the kind of win this milestone banks) inflates every marginal
  row and trips the gate. Proven empirically below.
- Three warnings around fail-open/edge behavior and misleading operator output, plus three minor
  info items.

## Critical Issues

### CR-01: Size enforce gate reports a FALSE regression when the core bundle shrinks

**File:** `scripts/size-baseline.mjs:104-141` (`diff` + `enforceSizeExitCode`); metric produced at `scripts/size-baseline.mjs:78-82`

**Issue:** `enforceSizeExitCode` runs over `result.rows`, which `diff()` builds from BOTH the
absolute `entries` rows AND the derived `marginal` rows (`diffMap(baseline.marginal, current.marginal, 'marginal: ')`).
`marginal[name]` is defined as `entries[name] - core` (line 81). When the core bundle shrinks and
component entries are unchanged, every marginal value *increases* by the amount core dropped — so
each marginal row shows a positive delta and the gate returns exit 1, failing on an improvement.

Reproduced against the committed `api/size.baseline.json` (core bundle shrunk 665 B, component
entries flat — `measure()` recomputes `marginal = entry - core`):

```
   core bundle -665                                   <- the improvement
   marginal: button (light deep import)     +665
   marginal: data-grid (heavy deep import)  +665
   marginal: popover (overlay deep import)  +665
enforceSizeExitCode => 1                              <- gate FAILS on a win
```

The enforce contract (regression-CEILING: "a shrink passes") is violated because `marginal` is a
*relative* measure, not an absolute payload size. A core growth is still caught correctly via the
`core bundle` entry row, so the marginal rows add no protective value on the growth side — they only
create false positives on the shrink side. The plan (`11-01-PLAN.md:22`) explicitly asked to enforce
on "any entry or marginal row," so this is a design flaw carried faithfully into code; it is still an
incorrect exit code on legitimate input. Soak (`continue-on-error`) contains the blast radius today,
but the stated intent is to un-soak, at which point a core optimization is CI-blocked. The enforce
tests (`test/size-baseline.test.ts`) only exercise synthetic single-`core bundle` rows and never a
marginal row, so this path is untested.

**Fix:** Exclude the derived `marginal` rows from the enforce decision (keep them report-only, the
same way wall-clock is structurally excluded in perf-diff). Tag the rows in `diff()` and filter:

```js
// in diffMap, tag derived rows:
return { name: prefix + name, base: ..., current: ..., delta: ..., status, derived: prefix !== '' };

// enforce only over absolute entries:
export const enforceSizeExitCode = (result, { tolerance = SIZE_TOLERANCE } = {}) => {
  const rows = (result?.rows ?? []).filter((r) => !r.derived);
  const regressed = rows.some((r) => r.delta != null && r.delta > perRowMargin(r, tolerance));
  return regressed ? 1 : 0;
};
```

Add a regression test asserting a core-shrink-only diff (with recomputed marginals) returns 0.

## Warnings

### WR-01: `size-baseline --enforce` fails OPEN and WRITES the baseline when it is missing

**File:** `scripts/size-baseline.mjs:195-202`

**Issue:** On the "baseline absent" edge, EVERY mode — including `--enforce` — calls
`writeBaseline(current)` and `process.exit(0)`. Two problems: (1) it is **fail-open** — deleting
`api/size.baseline.json` silently turns the size gate green instead of failing; (2) it **writes** the
committed baseline under `--enforce`, directly contradicting the file/CI comments that `--enforce`
"reads the committed api/size.baseline.json only (never writes it)" (`ci.yml:171-173`,
`size-baseline.mjs:208`). The sibling `perf-diff --enforce` handles the same edge more safely: it
prints "New baseline …" and exits 0 **without** minting a file (`perf-diff.mjs:246-255`). The two
enforce gates should behave consistently on a missing baseline.

**Fix:** Under `--enforce`, do not write on the missing-baseline edge. Either exit non-zero (treat a
missing committed baseline as a gate failure) or, to mirror perf-diff, print guidance and exit 0
without writing — but never `writeBaseline` in enforce mode.

### WR-02: `perf-diff` crashes instead of exiting 0 when the current report file is absent

**File:** `scripts/perf-diff.mjs:246-257`

**Issue:** The CLI guards `existsSync(baselinePath)` but never `existsSync(currentPath)`. If
`api/perf.json` is missing (e.g. the harness produced no output), execution reaches
`diff(load(baselinePath), load(currentPath))` and `load()` throws an uncaught `ENOENT`, exiting with
a stack trace and code 1. In report-only mode (`npm run perf:diff`, no `--enforce`) the documented
contract is exit 0; instead it crashes. Under `--enforce` it also crashes rather than emitting the
structured gate message.

**Fix:** Add a symmetric `existsSync(currentPath)` check before diffing:

```js
if (!existsSync(currentPath)) {
  console.error(`perf-diff: current report not found: ${currentPath}. Run \`npm run test:perf\` first.`);
  process.exit(2); // usage/setup error, not a drift failure
}
```

### WR-03: Both enforce scripts print "drift never fails the build" immediately before failing the build

**File:** `scripts/perf-diff.mjs:196-198` + `:257-258`; `scripts/size-baseline.mjs:165-166` + `:204-205`

**Issue:** `formatReport()` is printed unconditionally before the enforce branch, and its footer
reads "Report-only this phase (D-08): count drift never fails the build; wall-clock never gates."
(perf) / "Report-only this phase (D-08): drift never fails the build." (size). Under `--enforce` this
message prints and then the script exits 1 and fails the job — the exact opposite of what the footer
claims. Confirmed: on a drifted size diff the last report line is literally
`Report-only this phase (D-08): drift never fails the build.` An engineer debugging a red CI job will
read a contradictory message.

**Fix:** Make the footer mode-aware — suppress or invert the "report-only / never fails" line when
`--enforce` is active (e.g. pass an `enforce` flag into `formatReport`, or print the footer only in
the non-enforce branch).

## Info

### IN-01: `perf-diff` positional validation checks only the first arg for a stray flag

**File:** `scripts/perf-diff.mjs:240-244`

**Issue:** `if (!baselinePath || !currentPath || baselinePath.startsWith('--'))` validates that the
baseline arg is not a flag, but never checks `currentPath.startsWith('--')`. An unknown second flag
(`node scripts/perf-diff.mjs base.json --bogus`) passes validation and later crashes in `load()`
rather than printing `USAGE` and exiting 2.

**Fix:** Add `|| currentPath.startsWith('--')` to the guard so an unrecognized flag yields the exit-2
usage error the header documents.

### IN-02: `cell()` escapes only `|`, not newlines or backslashes

**File:** `scripts/build-cost-cards.mjs:29`

**Issue:** `cell()` replaces `|` with `\|` and the header claims markdown-injection safety
(T-11-09), but a value containing a newline would still break the surrounding table row, and a
backslash-pipe sequence is not normalized. Input is maintainer-authored baseline JSON (numbers and
known metric keys), so real-world risk is low, but the injection-safety claim is narrower than
stated.

**Fix:** If the safety guarantee is meant to hold for arbitrary values, also collapse/escape newline
characters (e.g. `String(v).replace(/\\/g,'\\\\').replace(/\|/g,'\\|').replace(/\r?\n/g,' ')`).

### IN-03: Cost-cards "Scope" prose lists `combobox` as a heavy entry but it has no size row

**File:** `scripts/build-cost-cards.mjs:52-62` (rendered at `docs/cost-cards.md:6-11`)

**Issue:** The Scope paragraph names "heavy entries (`data-grid`, `combobox`)", but `combobox` is only
a perf scenario — it has no entry in `api/size.baseline.json`, so it never appears in the size table.
A reader scanning the size table for the advertised heavy entry will not find it.

**Fix:** Clarify the prose (e.g. "heavy: `data-grid` (size + runtime), `combobox` (runtime only)") so
the Scope text matches the tables the generator actually emits.

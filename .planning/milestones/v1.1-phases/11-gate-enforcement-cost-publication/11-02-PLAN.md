<objective>
Flip the runtime perf baseline guard from report-only to enforcing on COUNT metrics only (GATE-02), reusing the enforce->soak->CI pattern proven by the GATE-01 tracer (11-01). Wall-clock stays structurally report-only. The newly-enforcing `perf` step is soak-staged with a temporary `continue-on-error: true` (GATE-03) so cross-CI-run count variance is characterized without ever blocking a publish.

Purpose: Lock in the banked Phase 9 runtime-count wins so a count regression red-builds CI, while the volatile wall-clock metric — the whole reason the design exists — can never trip the gate.
Output: `scripts/perf-diff.mjs` gains an `--enforce` mode; the `perf` CI step runs it under a soak `continue-on-error`; a unit test pins that wall-clock can never set `hasDrift`.
</objective>

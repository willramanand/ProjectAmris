<objective>
TRACER plan (RPERF-01 + RPERF-04 for data-grid). Prove the entire Phase-9
measure→tune→re-measure loop end-to-end on ONE component before the other two
expand off it: build the reusable count-probe primitive in the perf harness,
refactor the data-grid sort into a nameable, wrappable compute method, memoize it
by source-identity (D-02), and demonstrate the new sortComputes count drops while
the sorted output, Lit lifecycle counts, DOM node counts, and the accessibility
DOM stay byte-identical.

Per RESEARCH F-1: the committed perf harness only counts update/updated/render +
nodes — none of which move when you memoize work INSIDE a render. So the "count
improvement" bar (RPERF-01) is unmeasurable until a first-party sortComputes probe
is built. This plan builds that probe (the load-bearing spine every later RPERF
plan reuses) and validates it against the data-grid memo.

Purpose: bank the clearest count + wall-clock win (sort re-clone on every render)
with the smallest regression surface, and prove the measurement machinery works.
Output: countMethod harness export, data-grid identity-keyed sort memo, sortComputes
wiring, and a report-only data-grid a11y snapshot guard.
</objective>
